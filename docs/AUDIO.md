## 재생과 동기화

`flapMotion.ts`가 문자판과 소리의 공통 일정을 만듭니다. 한 장 160 ms, 칸별 0–180 ms 시작 차이를 사용합니다. 한 칸이 바뀌면 각 착지에 짧은 녹음을 한 번씩 재생합니다. 전체 판에서는 타격 사이 최소 간격과 동시 재생 제한에 따라 일부 타격을 생략합니다. 화면의 정상 회전 순서와 속도는 그대로 유지합니다.

기본 화면과 `?demo=rotors` 모두 회전 횟수를 고정 목록의 전진 인덱스 거리로 결정합니다. 숫자판은 0–9, 출발·도착은 각각 5개의 글자판입니다. 96개 역명을 분해해 중복을 제거한 97개 글자와 빈칸 한 장을 모든 역명 칸이 공유하며, 각 글자판의 착지마다 타격음을 예약합니다. 같은 글자는 움직이지 않습니다. 이 순차 회전에는 6–12장 제한이나 중간 글자 건너뛰기가 없습니다. 현재 위치·지연의 숫자 외 문자는 기존 6–12회 효과를 사용합니다.

원본의 주 타격은 약 29.297 ms 지점에 있습니다. 파일의 시작을 착지에 맞추면 타격이 늦으므로 `impact / playbackRate`만큼 먼저 재생합니다. 효과음의 주 타격과 판의 착지가 같은 목표 시각을 사용합니다. 오디오 장치의 출력 지연까지 측정한 것은 아닙니다.

MP3의 처음 65 ms를 사용하고 런타임에 2 ms 어택·8 ms 릴리스 페이드를 적용합니다. 재생 속도는 0.97–1.03배, 마지막 착지는 같은 녹음에 조금 더 큰 게인을 적용합니다. 서로 다른 여러 녹음을 추출한 것으로 표시하지 않으며, 별도의 모터 회전음을 겹치지 않습니다. 가장 느린 재생 속도에서도 한 장의 160 ms 안에 들어오는 구간만 허용합니다.

- 기본 음소거·초기 음량 30%, 칸 좌표에 따른 좌우 패닝, 동시 최대 8음, 겹치는 재생 구간에 따른 감쇠와 마스터 압축을 적용합니다. 미래 예약과 취소 페이드도 동시 재생 수에 포함합니다.
- 전체 보드의 선택된 타격 사이에는 최소 25 ms 간격을 둡니다. 가장 이른 유효 타격부터 25 ms 안에 마지막 착지음이 있으면 그중 가장 이른 착지를 우선하고, 없으면 가장 이른 타격을 선택합니다. 나머지 충돌 타격은 생략하며 선택된 시각을 뒤로 미루지 않습니다. 단일 칸의 160 ms 간격 타격은 유지됩니다.
- 칸별 최신 요청을 한 microtask에서 모아 큐를 갱신합니다. 타격 값과 등록 순서는 요청할 때 복사해 보존하고, 예약 구간과 그 뒤 25 ms에 들어온 타격만 음원 정보를 계산하고 정렬합니다. 먼 미래의 일정 계산을 첫 프레임 전에 몰아서 하지 않습니다. 칸별 세대 번호와 전체 취소 번호로, 페이지 연타나 음소거 뒤에 오래된 요청이 다시 등록되는 것을 방지합니다.
- 최적화 렌더러는 공유 준비 microtask에서 모든 칸의 위치를 먼저 읽고, `onPrepared`에서 오디오를 등록합니다. 오디오 flush는 첫 애니메이션 프레임 전에 실행됩니다. 위치 측정과 화면 쓰기를 칸마다 섞지 않으며, 글자와 로고의 원래 회전 계획 시각·좌우 패닝을 유지합니다.
- 고정된 보드 칸의 좌표는 초기 정착 중 일괄 측정해 보관하고, 위치가 바뀌지 않은 페이지 전환에서 재사용합니다. 크기·전체 화면·스크롤·글꼴·상위 레이아웃 변경 시 갱신하며, 색상만 바뀌는 지연 상태는 재측정을 유발하지 않습니다. 유휴 상태에서 반복 프레임을 요청하지 않습니다. 보드 밖의 칸이나 필요한 관찰 API가 없는 환경에서는 준비 단계에서 좌표를 직접 읽습니다.
- 20 ms 간격으로 **500 ms 앞까지** 예약합니다. 이는 재생을 500 ms 늦추는 기능이 아니라 Web Audio에 미래 재생을 먼저 전달하는 것입니다. 우선순위 판정은 그 뒤의 25 ms 후보도 확인하되, 예약 범위 밖의 승자는 다음 점검까지 보류합니다. 이미 예약된 타격의 시각은 유지합니다. 미래 예약 노드 수가 8개를 넘을 수 있지만 실제 겹치는 재생은 최대 8음입니다.
- 소리를 켤 때 게인·패닝 채널 32개를 미리 준비해 첫 예약의 노드 생성 비용을 줄입니다. 각 미래 예약은 자기 채널을 소유하고, 재생이나 취소 페이드가 끝난 채널만 자동화를 지운 뒤 재사용합니다. 쉬는 채널은 출력에서 분리하며, 임시로 늘어난 채널은 반환 시 32개를 넘겨 보관하지 않습니다. 음원 소스는 타격마다 새로 만들고 오프라인 미리듣기는 별도의 채널을 사용합니다.
- 실제 음원 예약에 성공한 뒤에만 인접한 충돌 후보를 버립니다. 예약 도중 시작 기한을 놓친 후보는 그 후보만 제외하고, 남아 있는 유효 후보를 다시 선택합니다. 실시간 시작 기한은 현재 AudioContext 시각으로 재확인합니다.
- 일정이 진행 중일 때는 화면 시계와 오디오 시계의 변환 기준을 고정합니다. 점검할 때마다 기준을 다시 잡으면 브라우저의 오디오 시각 갱신 단위 때문에 정상 타격이 25 ms 간격 제한에 걸려 빠질 수 있습니다. 큐·미래 예약·취소 페이드가 모두 끝난 뒤 새 일정을 시작할 때 기준을 다시 잡으며, 시작 기한과 500 ms 예약 범위는 실제 오디오 시계로 판단합니다.
- **타격 목표 시각에서 `impact / playbackRate`를 뺀 샘플 시작 시각**을 놓쳤으면 이벤트를 폐기합니다. 이전 구현의 80 ms 지각 허용과 현재 시각으로 당기는 보정은 제거했습니다. 화면 작업이 잠시 막혀도 지난 소리를 몰아서 따라잡지 않습니다.
- 새 값·페이지/필터 변경·행 제거·음소거·음량 0·탭 숨김 시 미래 예약을 취소하고 재생 중인 음원은 현재 엔벌로프 값에서 최대 8 ms 동안 줄인 뒤 정지합니다. 이미 끝났거나 정지된 컨텍스트의 노드는 바로 정리합니다. 종료 콜백이 늦어져도 오디오 시계로 종료 여부를 판단합니다.
- 동작 줄이기 설정에서는 플랩과 효과음을 생략합니다. 미리듣기는 사용자가 누를 때만 재생하며 전광판 음소거를 해제하지 않습니다.
- 브라우저에서는 외부 음원 서버에 연결하지 않고 빌드에 포함된 MP3만 읽습니다. 다운로드 실패 시 안내하고 음소거를 유지합니다.

화면 작업이 잠깐 멈춰도 이미 예약된 오디오는 원래 일정대로 진행하고, 화면은 복구 시 해당 논리적 단계로 따라갑니다. 500 ms 예약은 최초 예약 완료 후 100–400 ms 정지를 견디도록 검증하는 범위입니다. 최초 준비 microtask보다 먼저 막힌 작업에는 아직 예약된 소리가 없으며, 예약 범위를 넘는 장기 정지에서도 공백을 보장 없이 채우지 않습니다. 첫 착지까지의 정상 대기 시간(글자판 기준 160 ms + 칸별 시작 차이)과 페이지를 재전환해 이전 소리를 취소한 구간은 예약 누락에 따른 공백과 구분합니다.

## 검증과 미리듣기

`scripts/browser_audio.mjs`는 운영 빌드에서 실제 MP3를 디코딩하고 실제 Web Audio 그래프를 검사합니다. 미리듣기 출력은 `artifacts/flap-preview.webm`에 녹음하며 WAV로도 변환할 수 있습니다. 실시간 재생과 오프라인 미리듣기는 `audioPolicy.ts`의 타격 선택 함수를 공유하며, 오프라인 렌더링에는 실시간 지각 판정을 적용하지 않습니다.

`scripts/browser_audio_resilience.mjs`는 100·200·300·400 ms 메인 스레드 정지, 연속 페이지 변경, 음소거·탭 숨김을 검사합니다. 검사 전용 AudioWorklet으로 전체 믹서 PCM 샘플을 집계하여 메인 스레드가 막힌 동안의 출력도 피크·클리핑 검사에 포함합니다. 이는 운영체제나 실제 스피커의 출력 측정은 아닙니다.

`scripts/browser_audio_continuity.mjs`는 고정된 밀집 입력의 정상 실행과 100·200·300·400 ms 정지를 비교합니다. 타격 간격뿐 아니라 오디오 스레드에서 수집한 10 ms RMS 구간을 −55 dBFS 기준으로 분석해 실제 무음 길이도 비교합니다. 800 ms 정지는 별도 초과 부하 검사로 취급하며 밀린 소리의 몰아 재생이 없는지 확인합니다. 고정 입력용 번들과 PCM 계측은 검사 전용이며 운영 앱에 포함하지 않습니다.

`scripts/record_transition.mjs`는 브라우저 프레임과 동일 믹서의 소리를 공통 시계로 맞춰 녹화합니다. `scripts/record_transition_comparison.mjs`는 `KORAIL_VIDEO_SCENARIO=normal|stall`로 일반 페이지 전환과 400 ms 강제 정지 영상을 구분합니다. 두 영상 모두 변경 전 다음에 변경 후가 이어지며 실제 앱 믹서를 기본 30% 음량으로 녹음합니다. 정지 영상에는 실제 정지 시각에 표시가 나타납니다. `KORAIL_VIDEO_OUTPUT_DIR`로 결과 위치를 지정하며 기본 파일명은 `transition-normal-comparison.mp4`와 `transition-stall-comparison.mp4`입니다. 두 버전의 소리를 동시에 섞지 않습니다. 검사·녹화 계측 코드는 앱 번들에 포함되지 않습니다.

코드 검사, 실제 오디오 출력·종료·단일 문자 동기 측정, 클리핑 분석 결과는 [VALIDATION.md](VALIDATION.md)에 기록합니다. 실제 스피커·헤드폰에서의 청감 비교와 Safari/Firefox 검증은 별도입니다.
