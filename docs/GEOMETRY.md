# 물리 선로 매핑 관리

현재 `backend/data/segments.geojson`은 의도적으로 비어 있습니다. 이름 없는 도형을 목적지·열차 등급·역 좌표의 직선 연결로 채우지 않습니다. `catalog.json`의 두 노선은 선택 대상이고, 검증된 실제 구간의 등록 여부는 별개입니다.

## 등록 절차

1. 사용 가능한 원본 선로 데이터와 재사용 조건을 확보합니다. 원본을 그대로 보존하고 취득 시각·출처·파일 해시를 기록합니다. 병행 일반선과 분기 구간도 필요합니다.
2. 원본 좌표계를 확인하고 필요하면 EPSG:4326으로 변환합니다. EPSG:5179 값을 경위도로 표기하는 식의 좌표계 이름만 바꾸는 작업은 하지 않습니다.
3. 오프라인 준비 도구로 새 검토 파일을 만듭니다. 아래 경로·출처·라이선스는 실제 확보한 값으로 지정합니다.

```bash
.venv/bin/python scripts/manage_geometry.py prepare \
  /absolute/path/original.geojson /absolute/path/review.geojson \
  --source '실제 자료의 출처 URL과 버전' \
  --license '실제로 확인된 이용허락 문서'
```

이 도구는 네트워크 요청을 하지 않습니다. 모든 구간을 `line_id=null`, `verified=false`로 준비합니다. 원본 feature ID 대신 geometry 해시 기반 ID를 부여합니다. 기존 출력 파일은 덮어쓰지 않습니다. 도형 수정 시 해시와 검토도 갱신해야 합니다.

4. 실제 철도 시설 자료와 대조하여 각각의 물리 선로에 `line_id`를 배정합니다. 열차 서비스의 운행 계통 이름을 배정하지 않습니다. 긴 도형이 여러 물리 노선을 포함하면 실제 경계에서 분할하고 근거를 기록합니다.
5. 도형 정확도, 일반선 병행, 분기/교차, 좌표계, 개통일, 연결 관계, 데이터의 단순화 정도를 검토합니다. 경쟁 도형을 누락한 채 `neighboring_tracks_reviewed=true`로 설정하지 않습니다. 모호한 구간은 미검증으로 남깁니다.
6. 검토한 구간에 아래 메타데이터를 모두 기록하고 `verified=true`로 지정합니다. `catalog.json`의 `coverage`는 일부 구간이면 `partial`로 유지합니다. 전 구간 검증은 별도 `coverage_evidence`가 있을 때만 `verified`로 기록합니다.
7. 검토한 파일을 대상 폴더의 `segments.geojson`으로 배치하고 검증 도구를 실행합니다. 서버를 재시작하면 인덱스를 다시 만듭니다.

```bash
.venv/bin/python scripts/manage_geometry.py validate /absolute/path/reviewed-data
```

`KORAIL_DATA_DIR`은 이 `catalog.json`과 `segments.geojson`이 들어 있는 폴더입니다. 형식 검증은 실제 지도 정확도에 대한 독립 검증을 대신하지 않습니다. 검증 실패 시 서버는 시작 단계에서 오류를 내며 이전과 다른 임의의 데이터를 대신 사용하지 않습니다.

## 구간 메타데이터

각 Feature의 geometry는 원본 기반 `LineString` 또는 `MultiLineString`이어야 합니다. `properties`의 구조:

| 필드 | 내용 |
|---|---|
| `segment_id` | 안정적인 구간 ID. 중복 불가 |
| `line_id` | `catalog.json`에 정의된 물리 노선 ID. 미지정은 null |
| `verified` | 구간 매핑 검증 완료 여부 |
| `neighboring_tracks_reviewed` | 인근 경쟁 선로의 누락·모호성 검토 여부 |
| `source` | 원본 자료 URL·버전·취득 근거 |
| `license` | 실제 확인한 이용허락 문서 |
| `reviewed_by` | 실제 검토자 |
| `reviewed_at` | 검토일 |
| `evidence` | 노선 이름·구간 경계를 뒷받침하는 시설 자료·검토 기록 |
| `geometry_sha256` | 준비 도구가 생성한 도형 해시 (선택) |

검증된 구간은 필수 검토 필드가 하나라도 없으면 시작 단계에서 거부합니다. 미검증 경쟁 도형도 거리 판정에 남겨, 검증된 도형 하나만 남았다는 이유로 잘못 매칭하지 않습니다.

## 판별 기준과 한계

기본 후보 반경 70m, 다른 노선과의 거리 차이 35m 이하는 `ambiguous`입니다. 거리 점수는 `1 - distance / (2 * tolerance)`이며 기본 최소 점수 0.65를 적용합니다. 즉 후보 검색 반경 안에 있어도 너무 멀면 `unknown`입니다. 점수는 휴리스틱이고 검증된 확률이 아닙니다.

이전 관측보다 120m/s × 경과시간 + 150m 이상 이동한 좌표는 위치 도약으로 보류합니다(5분 이하 관측 간격). 다른 노선으로 바뀌면 2개의 서로 다른 원본 시각에서 관측되어야 확정합니다. 이 과정에서도 이전 노선에 계속 표시하지 않고 `ambiguous`로 제외합니다. 반경 밖으로 나가면 즉시 `unknown`으로 바꿉니다. 사라진 열차의 이력은 삭제합니다.

이전 위치로 속도·노선 변경의 연속성은 검증하지만, 노선망의 방향·위상·전체 경로 탐색은 구현하지 않았습니다. 장시간 관측 공백, 터널·역·고가 교차, 인접 선로가 누락된 지도, 제공자 좌표 오차를 거리만으로 해결할 수 없습니다. 원시 GPS 정확도와 개별 측정 시각도 없으므로 실제 열차별 정답 데이터와 비교하기 전 정확도 수치를 제시하지 않습니다.

`StationLineMapping`은 역의 소속 노선만 뜻합니다. 울산 선택 시 경부고속선 **전체 중 검증된 구간**의 열차를 조회합니다. 울산에 정차하거나 가까운 열차로 범위를 바꾸지 않습니다. 출발역·도착역·KTX 여부는 선로 매칭 입력이 아닙니다.
