# 정차역·운행 노선 데모

`?demo=services`는 2026-10-26에 저장한 실제 위치 기록에 공식 시간표의 정차역·운행 계통을 연결합니다. 시작 화면은 울산 정차 열차입니다. `?demo=rotors`, `?demo=performance`와 일반 화면의 기존 물리 선로 필터는 유지됩니다.

## 자료와 적용 범위

| 자료 | 공식 파일 | 시행일 |
|---|---|---|
| KTX 시간표 | [코레일 XLSX](https://www.korail.com/file/cubedata/COMMON/jfile/202608/25/202608251a036897009480.xlsx) | 2026-09-01 |
| 일반열차 시간표 | [코레일 XLSX](https://www.korail.com/file/cubedata/COMMON/jfile/202608/25/202608251a036890aa0430.xlsx) | 2026-09-01 |

두 파일은 코레일이 2026-08-25 게시한 판본입니다. [공식 시간표 목록](https://www.korail.com/com/userBoard.do?mode=list&schBcid=ticketTable)에서 후속 KTX 시간표(게시물 26041)와 일반열차 시간표(26186)의 시행일이 모두 2026-11-01임을 확인했습니다. 따라서 생성기는 9월판을 11월 1일 이전에만 허용하고, 이번 산출물은 기록일 2026-10-26에 고정합니다. 별도 임시 운행 변경을 모두 확인한 것은 아닙니다.

원본 파일 SHA-256:

- KTX: `cf69ea35e0b6ad9fb82c0e0b44f60833e34eadab55ea610eaf6784622351e9d0`
- 일반: `2c1531ebce6ffd9aa18f51cc91d8fe4bffd7d95093dc970e21f5cc1964d3b61d`

원본 XLSX는 저장소에 포함하지 않습니다. `frontend/src/serviceTimetable.json`에는 공식 URL·시행일·해시, 참조 시트·셀, 운행요일, 정차역 및 미확인 사유가 기록됩니다. 소스가 바뀌면 생성기가 해시 불일치로 중단하므로 새 판본의 구조와 적용일을 검토해야 합니다.

## 연결과 필터 기준

- 열차번호, 운행일, 시발역·종착역, 양끝 예정시각이 모두 일치하고 해당 요일에 운행하는 시간표만 사용합니다. 번호의 앞자리 0은 비교할 때만 정규화하고 원본 번호는 보존합니다.
- 시간표에 실제 시각이 있는 역만 정차역입니다. 숨겨진 0값은 무정차이며, 양수인 다음날 자정과 구별합니다. 홍성 순환처럼 같은 역에 두 번 정차하면 순서를 보존합니다.
- 일반열차의 `…선 경유` 표시는 시트 밖 정차역이 있음을 뜻합니다. 전체 정차 패턴을 확인할 수 없는 열차는 미확인으로 남깁니다. 출발·도착역이나 현재 위치 문구로 중간 정차역을 추정하지 않습니다.
- 역 필터는 해당 열차의 전체 정차역 목록에 선택 역이 있는지 확인합니다. 아직 도착하지 않은 열차만 거르는 기능은 아닙니다. 노선 필터는 시간표 시트의 운행 계통이며, 역과 노선을 함께 선택하면 두 조건을 모두 적용합니다.
- 미확인 열차는 전체 목록에는 표시하고 역·노선 필터에서는 제외합니다. 실시간 선택은 기존 수집 꺼짐 상태를 유지하며 과거 시간표를 실시간 자료처럼 표시하지 않습니다.

| 기록 표본 | 전체 | 시간표 연결 | 미확인 |
|---|---:|---:|---:|
| 14:14:45 KST | 145 | 128 | 17 |
| 14:15:36 KST | 148 | 131 | 17 |

173개 역, 11개 운행 계통을 포함하며 최신 기록의 울산 정차 열차는 19대입니다. 이는 이 기록에 포함된 열차의 범위이며 전국 시간표 전체를 뜻하지 않습니다.

미확인 17대는 시종착역·시각 불일치 2대(426·520), 다른 노선 시트에 걸친 불완전한 정차 목록 11대, 해당 요일 시간표에서 번호를 찾지 못한 4대(2017·2018·2020·2513)입니다. 426·520은 기록이 용산 종착인데 시간표는 서울까지 운행하므로 제외했습니다.

## 교차검증과 후속 API 연결

KTX 경부선 시트의 31번(`B50`, 서울 11:58→부산 14:42)은 울산 정차가 있고, 35번(`B57`, 서울 12:58→부산 15:47)은 울산 칸 `S57`이 0입니다. 같은 노선·시종착역이어도 두 열차의 울산 필터 결과가 달라야 합니다.

[한국철도공사 열차운행정보](https://www.data.go.kr/data/15125762/openapi.do)가 연결하는 [인증키 없는 공식 예제 화면](https://openapis.korail.com/samples/public/run/travelerTrainRunInfo)에서도 2026-10-26의 `00031`번, 울산(`3900896`), 경부선(`01`), 정차구분 `여객승하차`(`11`)를 확인했습니다. 공개 예제는 페이지당 최대 10건이며 데모는 이를 반복 호출하지 않습니다.

정식 API `https://apis.data.go.kr/B551457/run/v2/travelerTrainRunInfo2`는 인증키가 필요합니다. 명세상 과거 3개월부터 전날까지 운행정보를 제공하며, `travelerTrainRunPlan2`는 과거 3개월부터 이후 1개월까지 계획을 제공합니다. 추후 실시간 자료에 연결할 때에는 과거 실제 운행정보와 정차 예정 자료의 범위를 구분해야 합니다.

## 재생성과 검증

원본 파일을 다운로드한 다음 `openpyxl`이 있는 Python 환경에서 실행합니다. 런타임 서버에는 이 패키지가 필요하지 않습니다.

```bash
python -m pip install 'openpyxl>=3.1,<4'
python scripts/import_service_timetable.py --ktx /path/to/ktx-20260901.xlsx --regular /path/to/regular-20260901.xlsx
python -m unittest discover -s scripts -p test_service_timetable.py
```

```bash
cd frontend
npm ci
npm test
npm run build
```

저장소 루트에서 오프라인 HTML을 만듭니다. 브라우저 검증에는 Playwright와 Chromium이 필요하며 기존 스크립트와 같은 `KORAIL_BROWSER_MODULE`, `KORAIL_BROWSER_EXECUTABLE` 환경변수를 지원합니다.

```bash
node scripts/package_rotor_demo.mjs --services
node scripts/browser_service_demo.mjs
```

브라우저 검증은 울산 정차/통과 구분, 상세 출처, 역·노선 교집합과 전체 노선 복귀, 페이지 초기화, 두 기록 표본, 실시간 비활성 상태, 데스크톱·모바일 화면과 오프라인 추가 요청 없음을 확인합니다. HTML·스크린샷·검증 결과는 `artifacts/station-service-demo*`에 저장됩니다.

2026-11-14 재검증에서 프런트엔드 181개, 시간표 변환 10개, 백엔드 69개 테스트와 프로덕션 빌드가 통과했습니다. Windows 전용 커널 mutex 테스트 1개는 Linux 환경에서 건너뛰었습니다. 오프라인 브라우저의 기능 검증 9개도 통과했으며, 1440px·390px 화면에서 가로 넘침과 브라우저 오류, 추가 네트워크 요청이 없었습니다. 별도 검토에서 131대의 정차 순서 1,560개를 공식 XLSX의 출처 셀과 대조하여 불일치가 없음을 확인했습니다.
